## What it is
The one moment the operator can learn that a responseMap key reaches nothing, or that a field the capability expects has no key.
Nothing at registration refuses a key under any other name, and a collection ends ok with nothing observed.

## Notes
The draft keys every field by the document's own name, and the operator decides what to rename before applying it as much as after, which is why the reading is made over the draft's configuration too.
The draft answer carries no capability, so this reading is the surface's own.
UNDERDETERMINED, from the specification -- rules/integration/a-connector-configuration-surfaces-readiness-statements-carry-no-claim-no-rule-decides binds the statement this task builds to refusing nothing and to withholding no act submitting a registration beyond the one well-formedness withholds. No criterion of this task holds the surface to that.
A surface that states, for every well-formed configuration text it presents declaring a responseMap, which keys a registered capability reads, which reach none and which expected fields are unnamed -- and that, while a key is read by no capability or an expected field has no key, disables or hides the act submitting the registration -- satisfies every criterion as written while the readiness rule refuses it.
REMAINDER, from the specification -- The clauses of rules/integration/a-connector-configuration-surfaces-readiness-statements-carry-no-claim-no-rule-decides that bind the statements of the HTTP-connector-departure, subject-placeholder and credential-placeholder rules reach no criterion of this task; only the responseMap-coverage statement is built here. Belongs to the tasks of this epic that build those three statements.
ADVISORY, from the specification -- Criteria 1 to 3 turn on a capability's top-level output schema properties and on a capability being registered naming a connector. The governing rule constrains domain/integration/capability, which holds those attributes, and that node is not among this task's candidates.
Decision, beyond the covers — stand: domain/integration/capability is an unrelated, unchanged element this epic does not touch; growing the claim to cover it would be scope creep for a reference this task only reads, never redefines.
ADVISORY, from the specification -- Criterion 6 makes the statement over the configuration of a draft the surface states, and the rule's Description leans on rules/integration/a-connector-configuration-draft-response-carries-no-capability for the draft's answer carrying no capability. Decision, beyond the covers — stand: rules/integration/a-connector-configuration-draft-response-carries-no-capability belongs to the sibling epic drafted-answer-disclosure, which already covers it; this task only reads the draft's configuration as a second text to make the same statement over, and does not redefine what that answer carries.
