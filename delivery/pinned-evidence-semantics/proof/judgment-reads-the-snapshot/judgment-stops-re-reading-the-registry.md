## What it is
src/__tests__/unit/investigation/citation-validation.spec.ts is rewritten: every test that constructed a `HypothesisCitationContext`/`ValidateCitationsOptions` value carrying `outputSchemas`, or imported `capabilityOutputSchemaKey`, is rebuilt to construct `Evidence` values carrying their own `fields: FieldSemantics[]` directly, checked with no capability-registry fake anywhere in the file. The two former malformed-JSON/no-properties tests are removed — that behavior no longer belongs to `citesADeclaredField` (it moved to `field-semantics.ts`'s own `fieldSemanticsOf`, already covered by `field-semantics.spec.ts`) — and two new tests are added: one proving the field check is refused across evidence items (a field on one item never satisfies a citation naming a different item's concept), and one asserting, over the module's own source text, that no `outputSchemas`/`capabilityOutputSchemaKey`/`CapabilityOutputSchemas` remain in the file at all.

src/__tests__/unit/investigation/judgment-stage.spec.ts is rewritten: `capabilities`/`FakeCapabilityQuery`/`aCapability`/`Capability`/`CapabilityResolution`/`ICapabilityQuery` are removed entirely, since `JudgeHypothesesOptions` no longer declares a `capabilities` field and nothing in this file needs a capability-registry fake any more. Every fixture that previously registered a capability's output schema and pointed an `Evidence`'s own `capability_name`/`capability_version` at it now sets that `Evidence`'s own `fields` directly. The test that asserted a citation is checked against a "current" capability's registry answer (proving the old live-resolution behavior) is inverted into two new tests proving the opposite: a citation naming a field the evidence's own snapshot declared is accepted regardless of what a re-registered capability at the same name/version would now say, and a citation naming a field only such a re-registration would add is refused, since nothing in this call path ever reads a registry to find it. A new source-text test asserts `judgment-stage.ts` imports no `ICapabilityQuery`, reads no `capability-query.port`, and defines no `outputSchemasFor`. One doc-comment test's expected substring is updated to match this task's own rewritten prose ("those same snapshotted field names" rather than "each evidence item's declared field names"), since the implementation record discloses that every doc comment describing the prior live-resolution behavior was rewritten.

## Notes
Both files were read in full before any edit, and every pre-existing test's own name and assertion intent was preserved wherever its premise still held under the narrowed shapes — only the fixtures (capability wiring versus evidence's own `fields`) changed. The two tests whose premise the task's own instructions named as newly false (the "current capability schema" mismatch test in judgment-stage.spec.ts, and the "declared only under a different capability_name/capability_version" test in citation-validation.spec.ts) were replaced rather than merely patched, since their whole point — proving the citation check consults a live-resolved schema keyed by capability identity — is the exact behavior this task removes; the replacements prove the inverse the task's own criterion 3 and the scenario node state.

`npx tsc --noEmit` and the vitest suite were not run by this agent: this environment holds no shell tool, so neither command could be executed here. Both files were checked by hand against the current `citation-validation.ts` and `judgment-stage.ts` (read in full) for type-shape agreement (no `outputSchemas`/`capabilities` field on any constructed value, `EvidenceItem`'s actual `{concept, fields, concept_description} & ObservationOutcome` shape matched exactly in every assertion) and for behavioral agreement (each assertion's expected result was traced by hand through `isCitationValid`/`citesADeclaredField`/`isStructurallyValid`/`toEvidenceItems` as they now read). The caller's own captured run is what confirms `npx tsc --noEmit` and the suite actually pass.
