- field: statement
  unstated: This rule already states that the schema draft's two refusals answer under the same HTTP status and never under the same error value, and the two refusal rules already name the three fetch failures and the two error values, but no node states what either refusal discloses to its caller beside the error value — whether which of the three fetch failures occurred, the status an out-of-2xx answer carried, or the link the request named reach the caller at all, or are held only server-side, and what a refusal reporting OpenApiDocumentNotReadableError carries.
  decided: The OpenApiDocumentNotFetchedError refusal discloses, beside that error value, which of the three fetch failures occurred as one of network-failure, timeout or status-outside-2xx — that last carrying with it the status code the link answered — together with the link the request named, exactly as it named it, and nothing else of that fetch; the OpenApiDocumentNotReadableError refusal discloses, beside that error value, the link the request named, exactly as it named it, and nothing else of the document.
  why: Which of the three failures occurred is the whole of what tells the operator's two possible next acts apart — name a different link, or go and fix the far end publishing the document — and the link and the answered status are the caller's own input handed back and the far end's own public answer, so disclosing them tells the caller nothing about this system; everything else a failed fetch or a failed parse produces is an error's own message or unexamined content, which describes internal state or a document this operation never read, and separates no cause the operator would correct differently, so an unreadable document needs only the link that names where the correction is made.
