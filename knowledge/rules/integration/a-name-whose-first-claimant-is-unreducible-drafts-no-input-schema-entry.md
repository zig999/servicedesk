## Description

The order a-capability-schema-drafts-parameter-or-field-name-claimed-twice-favors-declared-order reads is read off the document's own declaration -- a part's location, then its position in the parameters array declaring it -- and whether a part's schema can be reduced to one JSON Schema type is no part of that reading, so a part standing first there stands first there still when its own schema turns out unreadable; a-part-both-unreducible-and-name-claimed-stands-in-unresolved-under-each-reason already reads the two triggers as firing on their own terms rather than one suppressing the other, and precedence passing on reducibility would instead let the type a schema happens to declare decide which part of the operation a name stands for.
a-capability-schema-drafts-input-schema-is-read-from-the-chosen-operations-parameters-and-fields fixes without condition that a name whose own schema does not reduce to one type declares no properties entry, so the name the first claimant holds carries none, and the draft's top-level required array -- which lists the names that object holds -- carries it no more than it carries any other unreducible name. An entry at that name holding a later claimant's type would state that the part the draft reads first at that name has a type the document never gives it, which is the guess a-capability-schema-drafts-input-schema-is-read-from-the-chosen-operations-parameters-and-fields declines when it discloses an unreadable type rather than choosing one.
Every displaced claimant keeps reason name-claimed-by-another-parameter because its name genuinely is claimed by a part the draft reads ahead of it, whatever became of that part's own type, and a reason naming the winner's unreadable schema would misstate why the displaced one is absent; the reviewing operator is left holding both facts apart -- one name whose type no document reading yields, and the other parts of the operation answering to it -- and settles them by hand, which is what the unresolved list is for.
