## What it is

Both manifest-presentation surfaces now resolve a pinned revision's own state across every page of its hypothesis's revisions listing, and explicitly present a "still being read" or "could not be read" window whenever any read this depends on is incomplete or fails, on the same terms whether the pin is on the default page or requires this task's own off-page resolution.

## Notes

The first build attempt (run/pinned-revision-state-off-page-corrective-resolve-the-pinned-revisions-state-off-page-build) passed clean, but the first suite attempt's test step failed on 18 tests across 6 files. Two failures (in this task's own new tests) were races -- a synchronous assertion sampled before the off-page fetch settled -- fixed by the test-author. The other 16 (across 5 files, 4 of them pre-existing and untouched by this task) were a real regression this implementation introduced: RevisionSelect's own `isLoading` gate had started depending on the new pin-state query's mount lifecycle, breaking its previously-independent branch decision. Fixed by hoisting `usePinnedRevisionState` to the component's own top level (called unconditionally, alongside `useManifestRowRevisions`) and reducing `PinnedRevisionStateBadge` to a purely presentational, hookless subcomponent, so the gate reads only `useManifestRowRevisions`' own `isLoading` again, exactly as before this task.
