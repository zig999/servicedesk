## What it is

Unit-level proof against runSimulateHypothesisPipeline directly (simulate-hypothesis-pipeline.spec.ts, mirroring investigation-pipeline.spec.ts's own established shape), against handleSimulateHypothesisRequest directly (simulate-hypothesis.controller.spec.ts, mirroring simulate-case.controller.spec.ts's own established shape) and against createProductionHypothesisSimulationRunner directly (production-simulate-hypothesis.factory.spec.ts, mirroring production-simulate.factory.spec.ts's own established shape), covering all nine of this task's criteria; one added status-map.spec.ts entry proving HypothesisNotInManifestError's own 404 mapping; and a real, end-to-end integration proof against createDiagnoseHttpServer(env) — reaching a real PostgreSQL database, a real HttpDeclarativeObservationSource and a mocked Anthropic client, exactly the convention simulate-case-server.factory.spec.ts already establishes — for criterion 9's own "for a real process" and the strongest available evidence that no investigation row is ever written. Three already-delivered test files (build-app.spec.ts, diagnose-e2e.spec.ts, diagnose-persistence-deadline-e2e.spec.ts) received the minimal companion `simulateHypothesis` stub/dependency their own literals now require, since BuildAppDependencies and BuildAppDependenciesInputs both gained that field — no behavior of theirs changed, and no new test was written over what they already proved.

## Notes

No BLOCKING or UNDERDETERMINED entry remains open against this task's own Notes at the time this proof was written: the eighth criterion's durations shape was already resolved via /analyse before the implementation began, and this proof's own durations tests pin that resolved shape (collection, judgment, total — no writing field) rather than re-litigating it. The task's own REMAINDER entry (rules/investigation/the-response-follows-the-record) names no implementation for this task to exclude — it observes only that the rule's premise belongs to the diagnose entry point, which this task does not touch — so no test is owed for it here, consistent with the rule that an entry naming no implementation is not one a test is invented against.
