## What it is

A pure translation step that reads a Subject's attribute-values, the collection's requester identity, and a connector's own opaque call configuration, and produces the concrete address, query, headers and body of one outbound HTTP request, plus wherever a credential the call needs is placed.
A single, shared substitution mechanism over one placeholder syntax ('${subject:<attribute>}', '${requester}', '${credential:<ENV_VAR>}') that never executes the configuration as code, sources a credential only from the environment by name at resolution time, and refuses rather than guesses when a designated Subject attribute or credential is absent or empty.

## Notes

The placeholder syntax, the descriptor's shape and the substitution algorithm are this task's own free technical design, per its own re-cut Notes; the scope's own illustrative descriptor format, JSONPath syntax and pseudocode are non-binding.
No adapter wires this resolver to any HTTP call yet — that lands in task/http-observation-runtime/http-declarative-observation-source, which depends on this task.
One divergence from STK-08 (no Zod schema for the credential's environment variable): the variable's own name is itself connector-authored data, not a fixed startup key, so it cannot join config/env.ts's closed schema; this follows the existing precedent of a credential read directly from process.env at its own point of use (anthropic-hypothesis-evaluator.adapter.ts's ANTHROPIC_API_KEY), while additionally failing closed where that precedent does not.
