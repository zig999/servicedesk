## What it is
The substrate the frontend standard presupposes, built over an absent tree: the ESM manifest with its scripts and authorized-only dependencies, strict compiler configuration, flat lint/style/build/test configuration wired to the vendored TUI submodule, and a minimal shell proving the @tui/ui/* alias and the TUI theme.css token chain resolve into a real compiled CSS bundle.
This is a substrate record and must not be read as a project with real screens: the only rendered content is a single Divider proving the wiring, and no e2e or unit spec exists yet -- both scripts complete via --passWithNoTests/--pass-with-no-tests rather than by asserting real behavior.

## Notes
Five build attempts preceded the passing one, each kept under its own run directory rather than overwritten: -build (install failed, no lockfile existed yet -- expected, resolved by a one-time npm install run outside the runner under explicit human authorization, mirroring the backend target's own precedent); -build-2 (install failed again, lockfile still stale after a mid-flight dependency-range edit); -build-3 (install passed, but this run only covered the install step, before the produces exemption's scope was reconsidered); -build-4 (typecheck failed: TUI's own vendored components import clsx/tailwind-merge/react through TypeScript's own directory-walking resolution, which needed frontend/tui/frontend/node_modules to exist as an ancestor of those files -- resolved by installing TUI's own already-committed package-lock.json independently, since TUI is a standalone package per its own CLAUDE.md, not a workspace member); -build-5 (lint failed on one missing return-type annotation in src/app.tsx, fixed).
Two rounds of standard amendments happened while this task was in flight, both authorized by a human before being applied: stylelint-a11y (abandoned since 2020, incompatible with the already-authorized stylelint ^16) was swapped for its maintained fork @double-great/stylelint-a11y; and tailwindcss plus @tailwindcss/vite were authorized after the first delivery attempt aliased TUI's theme.css's own `@import "tailwindcss";` to an empty stylesheet just to make the build pass, which would have shipped a build that succeeded while rendering no TUI style at all. A separate npm audit found 5 vulnerabilities (1 critical) rooted in vitest 2.1.9's bundled vite-node/esbuild; vitest was bumped to ^4.0.0 (matching TUI's own pin) and the audit now reports zero.
The secret-scan step runs and decides nothing because no authorized package carries a secretlint rule -- deferred rather than cited as a divergence, since no source file exists for SEC-02 or SEC-03 to anchor to.
