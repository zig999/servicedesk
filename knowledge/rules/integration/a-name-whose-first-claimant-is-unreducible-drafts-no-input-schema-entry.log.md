- field: statement
  unstated: No node states what becomes of an input_schema property name when the part winning it by the declared order — path parameter, then query parameter, then header parameter, then cookie parameter, then request-body field — is itself the one whose own schema does not reduce to one JSON Schema type; a-capability-schema-drafts-parameter-or-field-name-claimed-twice-favors-declared-order says the first claimant becomes that property "holding its own type" without requiring that its schema reduce to one, and a-part-both-unreducible-and-name-claimed-stands-in-unresolved-under-each-reason settles only the converse case of a later, displaced claimant being unreducible.
  decided: The first claimant in the declared order holds the name still and precedence passes to no later claimant; the properties object declares no entry at that name at all, that first claimant is named in the unresolved list with reason schema-not-reducible-to-a-type, and every other claimant is named there with reason name-claimed-by-another-parameter exactly as it would have been had the first claimant's schema reduced. Recorded as a new invariant, rules/integration/a-name-whose-first-claimant-is-unreducible-drafts-no-input-schema-entry, constraining domain/integration/capability-schema-draft, with a-capability-schema-drafts-parameter-or-field-name-claimed-twice-favors-declared-order's statement qualified so that the first claimant holds its own type only where that schema reduces to one type.
  why: The declared order is read off the document's own declaration — location, then position in the parameters array — and reducibility is no part of that reading, so letting precedence pass would make which part of the operation a name stands for depend on a property the order was never about, and would put a later claimant's type at a name the draft reads as the first claimant's; a-capability-schema-drafts-input-schema-is-read-from-the-chosen-operations-parameters-and-fields already fixes without condition that an unreducible name declares no properties entry and is disclosed rather than guessed at, and this keeps that reading and the sibling a-part-both-unreducible-and-name-claimed-stands-in-unresolved-under-each-reason's own — each trigger producing its own unresolved item, neither suppressing the other — true at the point where the collision and the unreadable schema meet on the winner instead of on a displaced part.
